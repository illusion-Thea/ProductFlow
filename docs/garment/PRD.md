## 1. 产品定位

基于现有 ProductFlow 自托管商品素材工作台，面向内部设计、运营和管理人员，建设服饰模特详情图生产能力。沿用商品、素材上传、文案节点、生图节点、连续图片会话、历史图库和下载入口，在现有商品工作台内增加十位置正式生产批次。

> 把一个 SKU 从商品事实确认推进到十份文案与底图提示词、人工确认、无宣传文字底图、程序精确排版，再到逐版本反馈、修改、下载和可追溯交付。

一个正式生产任务对应一个批次，批次固定为一个 SKU、一个输出规格、1–10 共十个位置；同一商品可关联多个任务，各自执行、取消、完成和结算。自由节点继续支持独立运行、预览、重试和下载；同一来源图可连接多个生成节点，各节点使用不同规格，无需建立正式批次，也不纳入生产批次首轮采用率。

## 2. 目标用户

### 2.1 角色与账号

仅设设计、运营、管理三类角色。设计与运营均可完成商品文生图流程；管理可测试功能，维护账号、团队、共享素材及模板，并负责发布、激活和回滚。

正式版使用管理创建的独立账号，记录稳定 UserID、所属团队、角色及启停状态；MVP一个账号只具有一个当前有效团队，管理角色负责整个部署的账号、团队、共享资源及发布管理。业务资源查看、下载和编辑仍遵循团队权限，不以共享口令识别操作人。企业统一登录、多团队切换和团队级管理员暂不接入，保留未来扩展能力。管理职责不自动授予修改他人个人任务的权限。

- 设计：高频制作服饰模特详情图，修改单图、文字和蒙版，并选择交付版本。
- 运营：维护商品事实、已确认卖点及规格，准备生产计划，反馈并下载所需图片。
- 管理：维护独立账号、团队、共享参考与模板，并执行符合条件的软件发布和恢复管理。

50–100 个独立账号、至少 20 人混合操作是目标规模，包含设计部 2 名高频用户；不据此承诺 20 路模型请求并行。

所有商品、正式任务及独立图片会话的整项“删除”统一按归档处理，包括尚未关联正式任务、只有自由画布的商品。归档隐藏默认列表项并保留归档访问入口、业务记录及历史，关联独立根资源仍分别鉴权。归档不级联归档、取消或删除关联任务和图片，不改变图片下载标记、留存时钟及有效依赖，也不把个人资源变成团队可写。图片仍可按原规则到期或手动删除，归档不保证永久保留文件。

有排队或执行中的工作时允许立即归档；此前已接受操作及其已确认阶段继续收尾，进度和结果在归档入口可见，需要停止仍须显式取消。归档后按原权限开放查看/下载、反馈及相应选择处置、取消、逐图删除/恢复和关闭未决事项；在该根资源内新增内容、生成、重试、改字/重绘或显式发起新的本地恢复，须先取消归档。归档与新操作接受须串行校验，不能通过并发请求绕过限制；归档不阻断归档前已接受阶段的结果登记。

归档与取消归档均校验原有修改权限并留审计。取消归档只恢复该根资源的普通入口和操作资格，不自动执行草稿、不恢复回收站图片、不重置图片留存或下载记录，也不改变任务主状态、原首轮及费用；已取消任务仍为终态。商品、正式任务及独立会话的归档标记各自独立，关联关系不传递归档限制。

### 2.3 身份与协作要求

账号禁用、移出团队及重要授权变化须及时约束已有会话。当前负责人也必须满足当前账号及团队成员关系要求；管理角色不获得他人个人任务的普通修改权。旧商品、连续生图会话、画廊、预览、下载、历史与对象引用均按根资源鉴权，不能保留共享口令或旧 URL 绕行入口。

个人或团队任务负责人被停用或移出任务所属团队后，管理可通过专用、受审计的交接操作指定该团队内有效的新负责人；独立图片会话适用相同规则。记录交接原因、执行管理者、前后负责人及时间，保留原创建者、团队、个人/团队范围、业务历史、费用及首轮快照。新负责人接续负责人身份及范围切换权，个人资源的修改权随负责人移交，团队资源仍由当前同队成员共同编辑；原创建者身份只作历史依据，不因重新启用自动取得已移交资源的负责人权限。交接不自动发起生产、恢复图片或变更范围，也不赋予管理日常编辑特权。

账号禁用、离队或失去修改权限会阻止该用户的新提交和其他失权操作，不撤销系统此前已经接受的生产操作。已接受但尚未派发的操作及其已确认后续阶段继续按原快照、额度和执行约束运行，保留原提交者及接受时的授权记录；不得借此追加新操作、扩大输入或绕过取消。需要停止存量工作时，由当前有修改权的用户显式取消。界面展示仍在执行的存量工作，交接不改写其原操作人。

完整系统配置、模型供应商档案及绑定、配置导入/导出仅允许系统管理角色在独立设置解锁后操作；持有解锁口令本身不授予管理权限。设计与运营可读取日常工作所需的脱敏模型能力、规格等运行时配置，不因此获得完整配置访问权。设置读取、预览和导出均不得回传已保存的原始密钥；配置导出保留非密钥配置及必要的凭据配置状态，迁移目标的密钥须通过授权配置过程补齐。

写入冲突时保留用户草稿并显示可操作原因；审计记录实际 UserID、TeamID、资源、动作、时间、前后版本及结果。系统清理和备份使用限定职责服务身份，不能成为任意编辑个人任务的通道。

## 3. 二开核心场景

### 3.1 商品素材链路

1. 使用独立账号登录，确认当前团队及角色。
2. 在团队商品入口上传至少一张商品原图，填写商品信息；创建正式任务草稿并明确任务的个人或团队范围。
3. 补充商品事实、依据及未知范围。正式批次绑定唯一 SKU 和一个输出规格。
4. 选择有参考或无参考分支，确认人物、场景、动作、共用风格、穿搭方式及固定排版模板。
5. 选择文案语言，默认中文；通过文本模型准备十份对应语言文案预览和底图提示词，分别绑定位置 1–10；校验后由用户逐项修改和确认。
6. 提交已确认计划，通过图像模型生成各位置的无宣传文字底图，保留原始首次尝试和执行记录。
7. 将底图适配到目标画布，由 Pillow 精确叠加已确认文字，生成默认待定的独立成品版本。
8. 在现有工作台内查看十位置进度、失败原因和候选；对已就绪图片先反馈、选择或下载。
9. 对指定位置改字、重生成或局部重绘，追加版本，并明确选择当前采用版；其他位置不重做。
10. 十位置均有当前采用版或明确放弃、且没有执行及未决事项后完成任务；原首轮统计单独结算。

以下规则适用于这条链路，原型和生产阶段分别按1.3执行。

#### 3.1.1 商品输入与事实（FR01）

单张原图可创建任务并准备十份内容；草稿可暂不绑定 SKU，正式生产必须绑定唯一 SKU。事实逐条记录依据、可核验视角、确认人和版本；背面、内部、开合、弹力、承托、哺乳或透气性能不能仅由外观图推定。

资料不足时可明确选择试生成，保留“待补资料/试生成”标记。正式批次计划只能使用已有依据，或改用不展示未知结构的姿势。商品原图、动作参考和目标效果示例分别记录，不能互相替代事实。

展示主图与商品证据原图分开记录。将生成结果设为展示主图或主图参考时，保留真实原图的证据身份及来源，不把生成图改标为证据原图；模型请求选择商品原图依据事实版本，不能仅按当前展示主图取图。

#### 3.1.2 参考、风格与模板（FR02–FR04、FR14）

参考图可选，无参考仍传商品原图。参考只提供动作、场景及构图，输出人脸全部AI生成。真人肖像（包括过期两年及当期素材）不得作为输出人脸来源，参考中出现真人脸也不沿用。素材来源须可回查。

人物外貌、肤色、姿势、构图及穿着允许文字设置；与参考条件冲突时由用户选择保留参考或切换文字分支，确认前不隐式混合。马来、印尼、菲律宾默认共用同一视觉风格版本。

穿搭模板与人工穿搭描述二选一，切换后不残留另一模式指令。固定排版模板与穿搭配置独立，任务内修改不改写共享模板；管理更新共享资源时生成新版本。

FR14参考库按商品及场景、人物、动作标签进行可解释匹配，候选可预览、替换、确认；零匹配可继续无参考路径，不偷偷使用停用或来源不合格素材。FR04的脸型、发型、坐姿、下装搭配预设库独立列P1，不影响FR14的P0范围。

#### 3.1.3 文案、批次和图文分层（FR05、FR06、FR09）

GPT6生成同一 SKU 的十份结构化文案与底图提示词，绑定1–10固定位置，供人工修改、确认。文案准备期间主状态为草稿，显示文案排队、生成、失败等技术进度；十条计划校验通过后进入待生成确认。文本失败或缺字段时保留草稿及具体原因，不进入待生成确认，不用模板结果伪装模型成功后自动生图。文本与图像具体官方API型号、账号能力、参数、费用分别记录。

文案内容语言提供中文、马来语（马来西亚）、印尼语（印度尼西亚）、菲律宾语（Filipino）四个选项，默认显示中文。用户选定语言后明确发起对应语言的文案生成，先展示文本预览；用户确认该语言及预览内容无误后，才将确认文字用于图片合成。菲律宾选项使用Filipino。文案语言与界面语言、市场元数据分开保存，切换界面或市场不自动翻译、重生成或修改已确认文字。

确认快照保存内容语言、预览文字版本及确认人/时间。更换内容语言后须生成并重新确认对应预览，旧版本和历史确认仍保留；未确认的新预览不得用于正式合成。对应语言的模型文本生成按实际请求单独记账，不能算作“改字零调用”；直接人工修改已确认文字并本地合成仍按零模型调用规则执行。字体覆盖、换行及溢出按所选语言的实际文字校验。

GPT image负责底图生成及蒙版编辑。底图不要求模型绘制宣传文案，确认文字作为独立图层，由程序精确排版。文字、底图、布局、模板、规格和合成成品分别版本化。

批次内每位置可选不同姿势、场景、已确认卖点及有/无参考分支；混SKU或混规格须拒绝或显式拆批。每位置的原始首次尝试及原首轮合成结果固定保存，失败仍占位置；重试、改字、重绘生成新版本。自由节点生成不纳入生产批次R0。

每位置保存独立的事实、内容语言、已确认文案预览、底图提示词、参考及模板快照。同一提示词的一组候选不能替代十份已确认计划，也不要求上一位置的生成图成为下一位置的输入。GPT6、GPT image 是需求中的模型方向，实际官方 API 型号、权限、SDK 和能力须按7.5冻结。

#### 3.1.4 图片反馈、修改与下载（FR07、FR08、FR12）

| 反馈 | 含义及边界 |
| --- | --- |
| 待定 | 尚未决定或重新评估；不自动重试、删除或延长保留期 |
| 采用 | 用户决定使用此版本；不等于已下载，不自动永久保留 |
| 弃用 | 用户决定不使用此版本；不等于删除，也不自动放弃整个位置 |

反馈绑定具体图片版本并记录操作者、时间和可选原因；更改反馈留历史。生成、重绘、改字产生的新图片默认为待定，技术运行成功不自动标采用。正式位置的交付候选、当前采用版和首轮成品只包含本位置的合成成品；底图、蒙版可按权限预览、下载并保留反馈，其待定反馈不单独阻塞任务完成。执行失败及其他未决事项仍须处置。批次位置可明确选定一个已采用的合成成品作为当前采用版，其他采用版本仍保留反馈。当前版本切换必须来自明确用户操作，迟到结果不自动切换。

仅改文字、字号、颜色或模板参数时复用底图，文本及图像模型调用增量均为零。文字缺失、溢出、字体不可用须明确报错，不自动删字或改写。改底图提示词、重生成或重绘需再次确认输入；仅操作指定位置，其余位置不重做。Alpha蒙版编辑对象为无宣传文字底图，编辑后再合成原文字层；区域外商品保持情况仍需人工检查。

成品文件修改前检查所需底图等依赖的生命周期。依赖底图在回收站时，在当前修改入口提示恢复；有恢复权限的用户确认后，系统直接恢复对应图片，无需用户去回收站查找，恢复成功后才允许继续修改。用户拒绝时，明确提示“不恢复所需图片，当前成品图无法修改”。恢复失败、无恢复权限或文件已清理时保留具体原因并阻止文件修改；不能未经确认自动恢复，也不能凭引用保护读取回收站底图继续改字。恢复后改字仍为零模型调用。图片入回收站或已物理清理时，有修改权的用户仍可调整反馈、撤销当前选择和关闭未决事项；这些记录操作不要求恢复文件，也不改写已结算首轮快照。

**下载统一规则：**三种反馈均可单张提前下载，无需整批完成、达到首轮目标或管理审批。只校验资源访问权限、文件正常可用及回收站状态。已取消任务的旧图、迟到保存的底图/成品同样适用，按资产类型明确标注“底图”或“合成成品”。回收站图片先恢复再普通下载，物理清理后显示文件已清理；下载对留存的影响见3.6。

输出规格沿用业务预设：9:16模特图、TikTok详情图1200×1200、Shopee详情图800×800；9:16绝对像素在接入验证时冻结。这些是产品约定的规格，不代表核验了外部平台当前全部发布规则。三类分别建任务和批次、生成独立文件，可复用有来源的底图或文案；同SKU三规格完整交付为三个任务、三个批次、共30个位置，各自计算首轮，不能用不同SKU各一规格替代。尺寸适配不得拉伸商品、裁掉关键结构或破坏文字。

当前采用版是独立选择，每位置最多一个，且只能来自本位置已采用的合成成品。撤销选中版本的采用时，同事务清除选择并重新评估位置。成功下载不自动采用；画廊收藏不替代反馈或成功下载记录。

字体文件及版本随模板保存，渲染前检查字符、字形、换行和溢出，不静默换字体。预览和下载引用同一成品版本。底图与蒙版统一方向、尺寸及 PNG 格式，Alpha 透明区域表示待编辑，保存预览坐标到原图的变换和输入顺序；模型原生尺寸与最终画布尺寸分别记录。

#### 3.1.5 商品质量与首轮统计（FR10、FR11）

Q01–Q09质量检查与图片反馈分别留档，质量缺陷在评估报告中呈现，不增加采用或下载审批门槛。具体检查见6.3。

`R0 = 原首轮被采用的位置数 / 10`，目标至少7/10。一次完整首轮评估需十个初次位置全部有明确执行结论，原首轮合成成品的反馈已处理；待定不能自动当采用。初次明确失败计入分母，取消或中止导致未执行的位置使首轮不完整，不能按7/7声称达标。不完整或未结算时仅显示进度，不展示最终达标结论。

首轮完整性按原首次生产尝试的端到端结论判断，模型已调用或底图成功不等于该位置已完成。取消时只有底图、尚无原合成成品且没有明确首次失败结论的位置，记为中断/不完整，不用取消替代失败来凑齐十位置。十张底图成功、七张成品采用、三张尚未合成且未明确失败后取消，只能展示进度，不能据此结算7/10达标。取消前已明确失败仍按原规则计入分母；可靠迟到的原首次执行结论按下文核对未结算评估，取消后仍禁止继续合成。

首次底图已成功，但合成或存储暂时失败时，若底图、确认文字及配置均未改变且不新增任何模型请求，本地恢复仍归原首次尝试，追加阶段恢复记录。恢复期间该位置首次执行尚未终结，不因一次技术错误立即结算为首轮失败；恢复所得原成品经反馈后可计入原首轮。到达预设有限截止时间仍未成功时停止自动恢复，保留待处理事项，由有修改权的用户明确选择继续本地恢复或结束该位置首轮尝试。选择结束后保留本地失败结论，后续修复不回填原首轮；不能把外部结果未知按此规则改记明确失败。改变内容/配置、重绘或新增模型请求仍属于修订或新尝试。

每位置记录首轮底图来源为新生或复用。复用底图按本批已确认计划第一次合成的成品可以计入本批R0，须保存源版本、复用关系及本批首次执行身份；不得把源任务的反馈或修复成绩直接继承为本批首轮。报告逐位置标注并按来源汇总，复用结果不能作为新生图效果验证证据；当前原型十个独立首轮要求保持不变。

结束未知等待后，原未知尝试及费用继续保留。原首次尝试的迟到结果可经可靠核对补齐尚未结算的首轮评估；只有原确认计划对应的完整合成成品及明确反馈满足计数条件，仅有底图不计采用。十位置执行结论和原成品反馈齐备后才能结算。新重试或修复结果不回填原首轮，已结算快照不自动改写；取消终态及禁止继续合成的规则仍生效。

任务未取消、原首轮尚未结算且原首次尝试仅返回迟到底图时，允许有修改权的用户明确确认，按原输入和配置补做本地合成。补合成须在该位置没有其他排队或执行操作时接受，两类模型调用增量均为零，结果仍归原首次尝试，仅补齐尚缺的原成品，不替换已有首轮版本；已明确结束为本地首轮失败的尝试不能借此恢复为首轮成功。已完成任务须由用户主动纳入当前工作后才开展该处理；已取消任务禁止补合成。执行版本、退出准入及文件恢复仍遵守各自规则，未结算首轮才可据此补齐。

后续修复采用不回填原首轮，当前采用数单列。评估结算保存原位置、原版本、当时反馈和质量检查快照；之后更改反馈、取消、过期或删除文件不改写已结算R0，需要纠正记录时追加修订说明。

### 3.2 连续图片会话

1. 保留独立图片会话入口；创建时选择个人或团队范围并记录当前负责人，按2.2授权；上传参考图、输入提示词和选择支持的生成参数。
2. 从任意候选继续，或显式选择参考参与下一轮，保留分支和候选历史。
3. 展示排队、运行、失败或结果未知；完成后刷新候选，重试必须由用户明确发起。
4. 将结果显式挂回商品作为参考或主图参考，或收藏到画廊，保留来源。
5. 为具体图片版本提供反馈、预览、下载、删除和留存提示，并统一检查资源权限。
6. 移动端保留主视图、会话抽屉、历史抽屉和底部生成面板的操作方式。

连续探索不强制建立十位置批次，不进入正式批次 R0；已有候选数量参数不代表十位置正式生产。用于正式计划的会话素材仍须完成商品依据、参考来源及输入确认。正式批次选定既有底图时保留真实来源和复用关系，不改写原首次尝试。

收藏是原图片版本的别名，沿用原根资源权限、反馈、下载和留存记录。挂回商品或跨任务/批次复用时，在目标根资源创建独立业务资产记录，保留源资源及源版本关系；反馈、下载标记和生命周期分别管理，底层不可变文件可以共享。复用生成图的新记录从复用成功时起获得30天正常区期限，保留原图生成时间，不继承原版本的成功下载标记；删除目标记录不连带删除源记录，共享字节须等待全部有效版本、依赖和租约释放后才清理。

复用系统内带文字的分层合成成品时，保留后续改字能力：在目标根资源同时建立成品、文字/布局快照和所需底图、蒙版等依赖的独立业务记录，并保存字体/模板版本及来源映射。目标负责人按目标资源权限编辑、删除及恢复目标侧依赖，不依赖其是否具有源个人任务修改权；源记录后续删除不改变目标记录状态。底层不可变文件仍可共享，生成图片依赖分别按独立复用记录计算留存。复用须检查全部必要源依赖的可访问性及可用状态；回收站依赖先按权限确认恢复，缺失或不可恢复时明确阻止可编辑复用，不静默降为只有成品像素。复制成品不继承源反馈、下载或首轮成绩，正式批次仍按本批计划首次合成确定R0。

### 3.3 商品 DAG 工作流

1. 在现有商品详情中使用节点工作台，保留商品上下文、参考图、文案生成及图片生成节点。
2. 保留内置场景模板追加、多选节点保存用户模板和连线形成 DAG 的能力。
3. 自由节点按需独立运行、预览、显式重试、取消和下载，同一来源图可连接多个不同规格的生成节点，不以十位置完成为前提。
4. 正式生产在同一工作台增加十位置批次视图，将位置计划与对应文案、底图、成品、反馈和历史关联；画布“运行全部”只执行自由节点，正式批次通过独立“确认并生成”入口提交。
5. 后台持久化业务操作、节点执行进度及原因；运行时沿用轻量状态轮询，结束后刷新商品、工作流和产物。
6. 模型操作统一受确认快照、幂等键、调用账本、实际请求配额和取消规则约束。
7. 移动端保留浏览、编辑及选择模式，以及平移、缩放、拖动、连线和多选能力。

节点画布服务于流程编排，节点场景模板与图文排版模板分别管理。自由图文排版画布 F03 仍为后续范围，不能用现有 ReactFlow 画布宣称已交付。

正式执行读取已确认的不可变计划及资产快照；修改、替换或删除画布节点不覆盖该快照，也不自动重跑正式位置。正式输入变化进入明确的修改与确认流程，保留原执行来源。

### 3.4 画廊与图片历史

1. 保留从连续生图结果收藏到画廊，以及在商品图库回看素材历史的入口。
2. 在画廊按生成时间浏览，查看来源商品/会话、提示词、尺寸、模型和具体版本。
3. 在图片详情区分底图、蒙版和合成成品，展示反馈、成功下载情况、生成及恢复时间、到期时间和调用费用来源。
4. 三种反馈的正常区图片均可按权限下载；收藏、采用、当前采用版与成功下载独立显示。
5. 删除或到期后显示回收站状态；已物理清理时保留历史元数据并明确文件不可用。

### 3.5 产品内帮助

1. 保留从导航进入帮助页、查看快速开始并返回商品工作台或连续生图入口的路径。
2. 在原有工作台、模板、运行状态与常见问题说明中，补充十位置正式批次、自由节点、三种反馈和当前采用版的区别。
3. 说明改字零模型调用、单图修订、未知结果、取消、首轮统计、完整下载、30天与7天留存及恢复规则。
4. 按角色说明协作权限和管理入口，区分已交付能力、阶段目标和待验证参数。

### 3.6 文件留存与恢复（FR13）

1. 生成图片按具体版本记录正常区期限，页面提示真实到期时间。
2. 用户可以直接手动删除图片；未下载图片到期也进入回收站，显示原因和剩余恢复期限。
3. 回收站7天内保证有修改权的用户可恢复；超过7天时，文件尚存且未进入物理清理仍允许按权限恢复，但不承诺超期文件一定保留。有有效引用的对象即使超期也暂缓物理清理。
4. 清理只移除符合条件的文件字节，保留历史、反馈、费用、来源与统计快照。

| 情况 | 正常区期限 | 回收站及最终处理 |
| --- | --- | --- |
| 新生成且未成功下载 | 从生成成功时起30天；反馈不改变期限 | 到期入回收站，再保留7天，无有效引用才清理文件 |
| 正常生成图跨资源复用产生的新记录 | 从复用成功时起30天；保留源生成时间，不继承源下载标记 | 新记录独立到期、恢复及下载；源记录不受影响 |
| 已成功下载的具体图片版本 | 保留至手动删除 | 手动删除后入回收站7天，再按引用清理 |
| 任意图片手动删除 | 立即离开正常区，不需要先弃用 | 回收站7天内保证可恢复；超期尚存且未进入物理清理时仍可按权限恢复 |
| 未下载图片恢复 | 从恢复时重新获得30天，原生成时间不变 | 新期限到期再入回收站7天 |
| 已下载图片恢复 | 仍保留至手动删除 | 不因恢复重置为未下载 |
| 下载历史不明的旧图片 | 迁入MinIO并标历史保护，不自动到期 | 用户可手动删除；不伪造历史下载事件 |
| 被执行中任务或其他编辑任务用作输入 | 引用保护不自动视为已下载 | 暂缓物理清理，引用释放后且7天期限已到才清理 |

保护引用解除不重新开始7天期限。恢复入口须检查真实文件及清理领取状态；已进入物理清理时提示清理进行中，已清理时提示无法恢复，不能先报告恢复成功。

“成功下载”按具体图片版本记录。预览、点击按钮、获取链接和中断下载不算成功。实现采用可审计的完整文件传输完成记录；浏览器是否最终保存到磁盘无法由服务器保证，界面不得作此承诺。同团队任一有权限用户成功下载该版本即可满足留存条件；另一生成版本重新计算。

文件字节与历史业务记录分开管理：图片清理后保留版本元数据、反馈、调用费用、来源与统计快照，标明文件已清理，不承诺仍可下载或修改图像文件。有修改权的用户仍可调整反馈、撤销选择、关闭未决事项，以便业务收尾。输出历史行本身不构成永久文件引用；执行输入、仍需编辑的任务依赖及有效资源引用才保护物理文件。被保护但已入回收站的文件不重新对普通下载开放。

底图、蒙版等生成图片同样按其具体版本留存；原始上传商品证据、共享参考、字体及模板资源按所属资源和有效依赖保护，不直接套用“生成后未下载30天”计时。正常成品保护其必要编辑依赖的文件字节及来源；依赖入回收站时，按3.1.4在修改入口提示并在用户确认后由系统原地恢复，拒绝或恢复未成功前禁止成品文件修改，引用保护不替代恢复操作。整体清理后不保证重建原文件。采用状态本身不增加引用保护。

完整下载前创建具体版本的 DownloadEvent 和有截止时间的 AssetLease，由认证文件服务传输；预览入口与下载入口分离。完整传输后登记失败须保留可核对事件、暂缓清理并报警。下载完成不能撤销后来接受的手动删除。

时间以 UTC 保存并按用户时区展示，30天和7天均按连续24小时计算；回收站7天从实际入站起算。恢复、下载、新引用与物理清理须互斥校验，不能同时报告恢复成功又删除文件；对象删除成功或确认不存在后才记为已清理。

迁移先备份并盘点商品、会话、画廊、JSON和复制文件的全部引用及归属。校验 MinIO 对象大小、SHA-256、尺寸和可读性后逐条切换；归属不明资源先隔离，本地旧文件只读保留。先建立可同时读取 LocalStorage/MinIO 的兼容基线，不能把仅支持本地路径的历史程序直接视为可回滚版本。

### 3.7 账号与团队协作（FR13）

1. 系统级管理创建、启停独立账号，分配一个当前有效团队和设计/运营/管理角色。
2. 创建者初始为当前负责人并选择任务范围；只有当前负责人可切换个人/团队范围，交接后该权限随负责人移交，切换后按当前权限约束已有会话。
3. 当前同团队成员可查看及下载个人和团队任务；修改权限按2.2执行。
4. 多人修改同一资源时检查预期版本，后到的冲突写入提示重新核对，保留编辑草稿。
5. 复制任务须有原任务修改权；新任务归复制者，范围显式选择，原任务、历史和统计保持。
6. 管理维护共享参考及模板时新增版本，任务内修改不覆盖共享资源，历史计划继续引用原快照。
7. 失权负责人名下的个人任务、团队任务及独立图片会话通过2.3的专用交接处理；同团队正常图片的独立复用按2.2授权，不等同于复制整个个人任务。
8. 用户撤权阻止新提交，已接受操作继续；停止存量工作由当前有修改权的用户显式取消，按2.3留存授权与操作记录。

### 3.8 软件发布和灾难恢复（FR15、FR16）

FR15管理软件发布包的Draft / Active / Archive状态、固定用户灰度、管理人工激活及兼容回滚。FR16提供数据库与MinIO的异机联合备份和恢复演练。部署隔离、每轮执行与续修的版本绑定、发布门槛及恢复目标统一定义在8.3。

软件回滚只切换程序；用户回收站用于恢复删除图片；灾难恢复用于生产数据或服务损坏后的恢复。三者不能互相替代。

1. 在隔离测试环境验证对应阶段需求，生成不可变发布包和报告。
2. 在独立生产环境登记 Draft，经就绪与兼容检查后，按稳定 UserID 对固定约20%用户开放灰度。
3. 每轮已接受执行固定 ReleaseID，正常接收操作期间，当前轮尚未结束时已就绪位置的提前修订沿用该版本；切版或停止灰度使旧版本开始退出时，停止向旧轮追加新修订，原轮收尾后由用户确认新轮并经兼容检查使用操作者当前分流版本。
4. 观察及路径覆盖满足要求后由管理人工激活；异常时停止候选新流量，按规则处理在途执行。
5. 仅回滚到与当前业务数据、对象和队列协议兼容的 Archive，业务数据不回退。
6. 异机保留数据库与 MinIO 联合备份，并在隔离环境计时恢复，按8.3的 RPO/RTO 目标验收。

### 3.9 任务状态与异常处理

#### 3.9.1 五类状态分开显示

| 状态对象 | 用途 |
| --- | --- |
| 任务主状态 | 下表九种业务状态 |
| 单图执行状态 | 排队、执行、成功、失败、结果未知等技术进度 |
| 图片反馈 | 待定、采用、弃用 |
| 文件生命周期 | 正常区、回收站、已物理清理；历史保护为独立标记 |
| 软件发布状态 | Draft、Active、Archive |

#### 3.9.2 九种任务主状态

以下十位置完成条件用于正式批次；自由节点运行及下载不以建立或完成十位置批次为前提。

| 状态 | 条件与后续 |
| --- | --- |
| 草稿 | 尚未提交图像生产；可保存并执行文案准备，显示文本排队、生成、失败等技术进度 |
| 待生成确认 | 计划已准备，等待人工确认后提交 |
| 生成中 | 初次生产仍有已接受的排队或在途操作；部分图片就绪可先反馈、下载及修订 |
| 待成品确认 | 当前生产轮次无排队/在途操作，存在待处理候选或反馈；有成功图片但部分失败也可在此处理 |
| 修改中 | 初次执行已全部结束，仍有已接受的修订排队或执行；旧文件保留，并按原留存规则可下载 |
| 处理异常 | 全局配置/资料等阻断，或本轮没有可处理成品且需要用户处置；显示具体原因 |
| 已完成 | 十位置均选定采用版或明确放弃位置，且当前工作无执行、待处理候选或未决事项；已关闭等待的迟到输出仅留档，不自动重开；可以由用户主动追加工作 |
| 取消中 | 已接受取消且仍有在途步骤；等待其返回或有限截止时间 |
| 已取消 | 无在途步骤或已完成收尾；保持终态，继续生产须复制新任务及新批次 |

接受取消后不再启动后续生成、重试或合成；迟到结果归原尝试留档，不恢复任务。无在途处理直接已取消。队列等待、部分失败和首轮达标不增加主状态。

其他位置仍在初次生成时，已有成品的位置允许明确发起改字、重生成或重绘；同一位置最多一个排队或执行中的操作。当前生产轮未结束且仍开放新操作准入时，提前修订追加独立操作及输入快照并沿用本轮ReleaseID；旧版本退出后的新修改保留为草稿，按8.3在旧轮收尾后确认新轮。主状态优先显示生成中；初次执行全部结束后，仍有修订在途则显示修改中。

6个采用位置加4个明确放弃可以完成，全部放弃也可完成。弃用一个候选不等于放弃位置；未决候选须明确采用、弃用或撤回修改，待定仍为未处理。对已生成的待定修订成品，“撤回修改”将该修订版标记为弃用，保留原当前采用版及全部历史，不删除图片、不触发模型，也不把该版转为仍待定的历史例外；同事务关闭该候选事项并按其余工作重新评估完成条件。未提交草稿可直接撤销，该操作不代替排队/在途工作的显式取消。撤销当前采用版需重新选择或处理位置，但下载不受影响。已完成任务的文件自然过期只改变文件可用性，不抹去历史完成事件；再次编辑时需要先恢复或补齐输入。

用户明确结束对未知结果的等待，可以关闭对应未决事项；原未知尝试和待核对费用继续保留，既不永久阻止业务收尾，也不改记明确失败或零费用。原结果迟到时，尚未结算的首轮可按3.1.5核对补齐；不得拿新重试结果替换原首次尝试。

用户已结束未知等待并完成任务后，原尝试的迟到成品仅按原尝试留档，反馈初始待定，不自动加入当前待处理候选、不切换当前采用版，也不重开已完成任务。只有用户主动纳入当前工作才形成新的待处理事项并重新评估主状态。历史迟到成品的反馈及未结算R0可独立处理，不要求先重开当前工作；已结算快照不变。

#### 3.9.3 故障与输入边界

产品输入上限25MB；所选模型对图片、蒙版、格式或数量有更严格限制时取更严格约束，并在提交前提示。不能把产品限额称为全系列API统一限额。蒙版与底图统一方向、尺寸和格式，记录预览到原图坐标变换。

明确失败可由用户重试或放弃；结果未知须保留原尝试及待核对费用，不能记零。取消与派发有确定接受顺序，超时收尾须由独立恢复机制完成，不无限等失联worker。输入变更重新确认；仅合成失败只重做合成，不重新生图。

存储失败只恢复存储登记，不重新请求底图。输入无效、权限不足、版本冲突、执行失败和结果未知须分别提示；所有可恢复问题均保留已有成功结果及用户草稿。取消与派发按同一任务锁确定接受顺序，已接受取消之后不再启动后续生成、重试或合成。

本地合成/存储恢复采用有限截止时间。超时停止自动恢复并等待人工处置，不自动结算首轮失败；继续恢复须显式接受新的本地恢复执行，结束首轮尝试须记录操作人及原因。首轮归属按3.1.5执行，取消、位置互斥、输入可用性和版本退出约束仍有效。

## 4. 核心对象

### 4.1 原项目对象的复用与扩展

- `Product`：复用商品名称、类目、价格和素材关系，补充正式生产所需 SKU、团队共享归属、事实版本及归档记录；关联正式任务保持独立根权限。
- `SourceAsset`：复用商品原图、参考图和处理后商品图，补充来源类型、证据用途、访问权限及存储映射。
- `CreativeBrief`：保留商品理解语义；模型理解不能自动成为已确认商品事实，事实以可回查的依据及确认版本为准。
- `CopySet`：复用结构化文案结果，关联十份位置计划、事实引用、人工编辑及确认快照。
- `PosterVariant`：复用海报/图片产物展示与历史关系，关联独立底图、文字、布局和合成成品版本。
- `ImageSession` / `ImageSessionAsset`：保留独立连续生图会话、参考图和生成图，会话独立记录团队、个人/团队范围、当前负责人及归档信息，统一来源、权限和资产生命周期。
- `ImageSessionRound` / `ImageSessionGenerationTask`：保留候选和持久化异步执行记录，对接明确尝试、结果未知和单次模型调用账本。
- `ImageGalleryEntry`：保留生成图收藏关系；收藏不自动改变采用状态或成功下载记录。
- `ProductWorkflow` / `WorkflowNode` / `WorkflowEdge` / `WorkflowRun`：复用商品 DAG 结构及运行记录，与正式批次位置关联；自由节点可独立运行。
- `CanvasTemplate` / `UserCanvasTemplate`：保留完整场景模板及用户节点组模板，与固定图文排版模板区分。
- `AppSetting`：复用运行时业务配置覆盖；模型能力、配置版本及凭据引用分开保存，不向前端回显密钥，不允许配置绕过禁隐式付费重试规则。

### 4.3 关键关系与执行约束

采用模块化单体，HTTP、应用编排、领域规则、基础设施分层。前端不持模型或MinIO密钥，服务端统一鉴权、记录请求并投递后台任务。保存短事务，模型请求不占用长数据库事务。

任务、计划、图片、反馈、模型调用、软件发布分别标识；不可变版本和审计记录保留真实操作人。API支持幂等键及预期版本，重复提交不新增业务操作，并发冲突返回明确提示。数据库与外部模型不具备天然原子性，结果未知不能通过重发掩盖。

模型SDK、HTTP、provider降级、队列及进程恢复均不得隐式补发付费请求。用户显式重试模型请求创建新操作和尝试；可能已计费时先提示潜在重复费用。输入及配置不变的本地合成/存储恢复追加阶段执行记录并保留原尝试归属。文件清理、消息投递或本地渲染的幂等重试不得进入模型调用链。

数据库迁移须兼容新旧程序，发布包、每轮执行及后续修订的版本绑定遵循8.3。所有旧下载、图库、预览及引用入口同步纳入第2章权限和3.6对象生命周期，不能留下绕行接口。

- 一个正式任务只对应一个批次；批次只能有一个 SKU、一个规格和1–10固定位置，位置唯一；一个位置同时最多一个已排队或执行的生产操作。
- 确认后的输入、版本及原首轮引用不可被后续修订覆盖；任务、计划、模板版本、图片版本与软件 ReleaseID 分开管理。
- 写操作检查幂等键、预期 `row_version`、当前权限和状态；同键同内容返回原操作，同键不同内容或版本冲突返回409。反馈、选择、放弃、删除/恢复和范围变更同样受保护。
- 业务操作与 Outbox 同事务写入，worker 原子领取阶段执行；派发前保存意图、配额及有限截止。可能已派发的请求保留未知，可查询可信的原请求结果，但不能通过查询新建生成请求。
- 模型 SDK 显式关闭自动重试，并核查 HTTP/代理、provider 参数降级、后备模型、队列及启动恢复。每次真实请求单独记账；未知费用不记零，本地合成或存储恢复不能进入模型请求链。
- 文本调用可归任务/计划，图像调用归位置，原型再关联 ExperimentRun；不强迫所有调用都有 ItemID。生产实际请求配额跨新旧 worker 共享，本地合成容量另计。
- 相同文件内容不合并不同版本的反馈、下载和留存记录；历史行和采用标记不构成永久物理引用。去重对象须等待全部有效版本、引用和租约释放后才可清理。

### 4.4 技术与架构基线

采用 React + TypeScript 前端、Python + FastAPI 后端；PostgreSQL 保存任务、反馈、版本、下载、引用及发布等权威业务记录，Dramatiq + Redis 负责异步投递，Pillow 负责确定性图文合成，私有 MinIO 保存对象。GPT6 文本和 GPT image 图像通过独立适配器接入，核验能力并保存配置快照。

沿用模块化单体：HTTP/展示层 → 应用编排 → 领域规则 → 基础设施适配；领域规则不直接调用模型 SDK、对象存储和消息队列。外部模型、文件传输等操作不占长数据库事务；模型及存储密钥只在服务端使用。

复用现有商品、上传、节点、模型调用封装、图片历史及下载界面；独立账号、反馈、回收站、用户灰度、兼容回滚和隔离部署仍须实现验证。源码差异、实体、接口、部署及故障处理详见 [TECH_DESIGN.md](./TECH_DESIGN.md)。依赖组合沿用经验证的锁文件，不为追求最新版整体升级；技术选型不等于效果、容量或恢复目标已达成。

- 保留移动端商品卡片、浮动分页、工作台底部工具栏、画布浏览/编辑/选择和连续生图抽屉操作；新增批次与详情操作也应可访问。
- 预览和下载引用同一成品版本，清理后不展示为仍可下载；历史完成事件和首轮快照继续可查。

- 本地恢复超时显示待处理及“继续恢复/结束首轮尝试”；已完成任务的历史迟到结果与当前待处理候选分开，主动纳入后才重开工作；旧版本退出时新修改保留草稿，收尾后再明确提交新轮。

### 8.2 原型进入完整产品化的条件

原型报告分别判断试验是否完成、是否允许进入完整产品化。放行须同时满足：

- 真实GPT6十份内容及商品图输入、无宣传文字底图到程序合成链路通过。
- 改字的文本与图像模型调用增量均为零，底图不变；请求额度、禁隐式重试和异常账本控制通过。
- 按冻结的内部标准完成十位置首轮，R_trial至少7/10；打样和修复不回填。
- 蒙版达到修改目标，区域外商品没有不可接受变化，文字层保持正确。

未满足时先如实报告结果、定位原因并提出针对性验证方案。可用本地检查验证的问题先本地验证；需要新真实模型调用时，明确目的、样本、参数、判断标准及次数，由用户确认后另建关联实验。原ExperimentRun最多12次的额度及原首轮结果保留，新实验不能用来绕过本轮限制。十二次是本轮原型限制，不是正式系统永久上限。

人工文案模式不能代替GPT6验证，7/10不能代替蒙版效果验证。以上是进入完整产品化的条件，不增加图片下载门禁，也不代表完整MVP或生产发布验收已经通过。

模板生产 MVP 还须验证单 SKU 三规格的三个独立任务/批次及30个位置、参考库匹配/零匹配、账号权限与交接、完整下载与留存恢复，并完成至少20人混合操作实测。各位置标注新生或复用底图，复用批次的R0不能充当新生图效果证据。模型请求并发、排队、保存及下载耗时、错误和成本分别报告；目标账号50–100，含2名高频设计，不虚构尚未冻结的时延与日产量。

生产实施同时遵循技术设计中的约束：

- 生产稳定版与候选版共享同一生产业务数据，测试环境资源独立；新旧协议必须双向兼容，容量实测覆盖双版本运行。
- 最多一个 Active 和一个接收灰度流量的 Draft；可保留其他 Draft 和全部 Archive。首次无 Active 时不虚构历史稳定版，按技术设计首发方案仅向固定试用账号开放，满足观察及人工激活后再全量开放。
- 发布请求检查幂等键与部署版本；先验证目标就绪再切换完整路由，核对期望/实际生效状态一致后才显示成功。就绪覆盖 DB/schema、Redis、MinIO、目标 worker、字体、模板和配置，探针不调用付费模型。
- 数据库迁移独立受控执行，先扩展兼容结构再切程序；普通回滚不执行破坏性 downgrade，不恢复旧业务数据库。
- 联合备份的数据库和必要对象须属于同一恢复点，保存 manifest 和摘要，复制期间保护所需对象；全部齐备才记可恢复。数据库备份链不能提前清理，不把 pg_dump 当作 WAL 恢复的基础备份。
- RTO 从故障发生计至服务就绪、主流程及完整性检查通过；隔离演练不自动重发历史付费请求。灾备快照中的排队、未派发及剩余额度不能证明恢复点到故障之间没有调用；恢复时先隔离可能受数据回退影响的模型执行和额度，结合独立可信证据核对。只有证明未派发且额度已核实的工作才可继续投递，否则保留未知及待核对费用，等待明确处置；不得通过恢复旧计数释放已消耗额度。
- 容量不足时告警并拒绝无法持久化的新任务，不删除受保护历史；长期已下载与历史保护文件、底图/蒙版/成品、回收站和备份分别估算，不能统一按37天容量计算。
