# 服饰模特详情图 AI 开发入口

版本：V1.4  
日期：2026年11月23日  
适用位置：`docs/garment/DEVELOPMENT.md`

本文件把 [PRD V1.13](./PRD.md) 和 [技术设计 V1.6](./TECH_DESIGN.md) 转为可执行的阶段与检查入口，并索引首次13项及复审7项共20项逐项确认。需求与验收以PRD为准，技术不变量以技术设计补充；任务状态、批准范围和执行证据沿用项目现有记录。本文件没有预先认定项目已完成任何二开阶段。

## 1. 开始工作的顺序

1. 读取仓库根目录 [AGENTS.md](../../AGENTS.md)、[Trellis工作流](../../.trellis/workflow.md) 及当前任务，确认用户本轮授权范围。保留Trellis托管块、已有任务和用户修改；不以本入口跳过现行任务创建、计划评审或执行门槛。已有有效授权不重复申请。
2. 阅读PRD §1.3–1.4，确认当前阶段和对应FR/AC；读取技术设计相关章节。原项目 [PRD](../PRD.md) 和 [ARCHITECTURE](../ARCHITECTURE.md) 用于了解原有能力，其旧范围与二开规则的已知差异按现行二开基线改造。
3. 按改动层读取 [后端规范](../../.trellis/spec/backend/index.md)、[前端规范](../../.trellis/spec/frontend/index.md) 及其相关子文档；若根目录CONTEXT.md及相关ADR已存在，沿用其中词汇与决策。不要另造并行的领域上下文体系。
4. 检查当前源码、依赖锁、配置解析、迁移、测试和运行入口，记录可复用点与缺口。文件或接口名称出现在文档中不等于目标行为已实现。
5. 找到当前最早尚未完成且可执行的任务。没有可复用证据时从M0开始；已有有效原型账本或验收证据时先核对，不能重置额度或重复执行已完成的付费请求。
6. 在现有工作流允许实施后，按“领域规则→应用编排→基础设施→API/界面→验证”做一个可独立验收的切片。复杂任务在既有任务目录内准备prd.md、design.md、implement.md，引用稳定FR/AC而不是复制整份需求并独立修改。

文档可直接作为编码输入，不表示可以一次启动全部阶段。真实调用、迁移、生产切换和清理由当前用户授权、阶段条件和环境事实共同确定。

### 2.1 第一个编码切片

M0核对后，优先把以下内容落实到当前已允许执行的M1任务：

1. 从现有商品/节点入口建立原型操作，保存单SKU、固定规格、十位置及已确认输入快照；正式任务与批次一对一，候选数量10不能替代十个位置计划。
2. 用最小持久化结构承载ExperimentRun、操作、尝试、模型请求和分层结果；沿用已有记录或新建契约均可，但不能只存在浏览器内存中。
3. 包装唯一可审计的模型派发入口，先保存派发意图、额度和截止，再进行单次请求；SDK、HTTP、provider、队列和恢复链同时检查禁重试。
4. 用替身走通四种内容语言选择（默认中文）、草稿文本准备及进度、十份预览校验与对应语言确认、无宣传文字底图、画布适配和Pillow合成；语言与UI locale分开，未确认对应预览不能合成，文本失败保留草稿及原因，不自动填模板伪装成功。
5. 改字复用相同底图并生成新合成版本，文本与图像请求计数增量均为零；局部重绘只提交指定位置底图与正确Alpha蒙版。
6. 在现有工作台展示最小位置映射、确认、进度、失败/未知和图文结果；保存草稿和旧版本。“运行全部”仅执行自由节点，正式批次独立确认生成并固定输入快照；正式交付候选只使用合成成品。
7. 检查重复提交、重启、未知请求、取消后续阶段及渲染/存储失败；保留原尝试与本地恢复记录，恢复超时停止自动执行并等待明确处置，未结算首轮不把暂时阶段错误当最终失败。未验证的正式账号、留存和生产治理仍列后续阶段，不能标为MVP已完成。

这些是可以直接拆入任务的交付项。AI应先查实际已有实现，复用满足契约的部分，只开发差额。

## 3. 参数、样本与阻塞处理

### 3.1 私有样本清单

原型使用用户提供的单SKU运动内衣商品原图、效果示例和文字意图。开发包不内嵌业务原图、账户密钥或真实生成产物。真实试验前，在当前任务的私有记录或明确的本地输入配置中登记下列内容；实际文件不放入可公开提交的docs目录。

| 字段 | 必须记录的内容 |
| --- | --- |
| SampleID / SKU | 样本稳定编号和本轮唯一SKU；探索样本与正式批次分别统计 |
| 文件及角色 | 实际可读路径、商品证据/效果示例/动作参考/文字意图；逐项记录，不凭文件名推定 |
| 完整性 | SHA-256、字节数、格式、方向和实际尺寸；不能只有URL或缩略预览 |
| 事实与未知 | 可核验视角、确认人、事实版本、缺失结构及限制展示的视角 |
| 模板与字体 | 实际字体文件/版本、固定排版模板版本、字符覆盖与溢出检查 |
| 试验配置 | ExperimentRun、真实模型配置版本、规格、所选内容语言及预览确认、有限截止、调用上限与已有消耗 |
| 评估基准 | 冻结的内部质量样例、Q01–Q09、首轮十位置映射、操作人及评估记录 |

提示词中“图1/图2/图3/图4”等指代必须对应真实已登记输入。没有对应文件时明确缺失；本轮无动作参考，不能把未知图号或效果示例当成已授权动作/商品事实。

样本缺失仅阻塞相应真实试验。可用人工构造的非敏感文件、可控替身和已知字体继续验证字段、额度、状态、尺寸与合成规则；此类结果不计真实商品保真、AI人脸或首轮采用率通过。

### 3.3 真实调用前的核对

- 读取原ExperimentRun及每次实际请求，计算剩余额度；失败、拒绝、超时都计数。不能因重启、复制、新建任务或切版本重置。
- 确认当前阶段和实验已有授权、真实输入与参数已冻结、关闭全部隐式付费重试、请求串行且n=1。
- 先做1张打样，再冻结内部配置和样例，执行十个首轮位置；最后验证改字和一次蒙版。图像合计最多12次，文本单独记账，未约定金额硬上限不得虚构。
- 内容语言默认中文；仅按用户所选语言及已授权范围生成预览并确认，切换界面或市场不自动调用文本模型。原型验证所选语言不等于AC72四种语言全覆盖，其他真实语言验证按后续阶段及授权记录，不能隐式批量执行四套实验。
- 明确失败等待显式重试/放弃，可能已派发的结果记未知并保留待核对费用。额度达到上限或必要参数缺失时停止对应派发，保留证据，继续可本地诊断的工作。
- 后续新真实实验按PRD §8.2提出目的、样本、参数、标准和次数，并沿用已获授权；需要新增授权时才请求确认，原实验及首轮不改写。

2. 每位置计划的四选一内容语言、对应预览版本及确认、底图提示词、事实引用、参考、模板/规格/配置；十条和事实怎样校验，语言与界面/市场如何分离。正式确认快照不随画布修改改变；自由节点可同源不同规格，展示主图不能代替商品证据。
3. 实际API/DTO字段、必填与长度/格式限制、幂等键及预期row_version；输入无效、未登录、无权限、冲突、失败和未知如何映射到现有错误结构。
4. 唯一约束、事务与锁，Outbox/worker领取、派发意图/配额/截止、取消和迟到顺序；同位置最多一个活动操作。原输入/配置的本地恢复保留原尝试，超时等待人工处置；完成后的历史迟到输出不自动纳入当前工作，未取消且未结算时允许明确补合成。旧轮退出原子停止追加，新修改保留草稿待确认新轮；原尝试溯源及实际恢复执行身份分别记录。
5. 输入输出资产类型、不可变键、父版本、尺寸/摘要、引用和租约；收藏共用原版本，复用成品同时建立目标图层及必要依赖的独立记录，保留来源，新生成图记录从复用起算30天且不继承下载标记。逐依赖校验源可读/可用及目标可写，源删除不改变目标状态；本地合成及存储恢复不进入模型链。
6. 前端服务端状态与本地草稿、轮询/缓存失效、空态/失败/冲突展示；预览与下载使用同一版本。正式候选、当前选择和首轮统计限定合成成品，按底图新生/复用分别汇总；中间底图待定不单独阻塞完成，但合成前取消且无明确首次失败不能据底图成功补齐首轮。撤回已生成待定修订记弃用并保留旧当前版，未提交草稿可撤销。回收站依赖在修改入口提示确认，系统恢复成功后才允许修改；拒绝提示“不恢复所需图片，当前成品图无法修改”，无需用户去回收站查找。
7. 数据迁移、旧入口授权及向后兼容影响、测试层次、适用AC和可回退方式。用户未授权的真实环境不执行迁移或清理。

不强制创建一套平行的商品系统。现有对象和界面可复用；新语义必须显式承载，不能把generation_count、JobStatus或收藏标记直接当正式批次、任务主状态或采用反馈。

## 5. 优先防止的旧行为回归

| 检查点 | 实施要求 |
| --- | --- |
| 应用失败自动重排、worker恢复运行任务 | 核对实际请求边界；付费失败不自动补发，可能派发保留未知 |
| 灾备旧快照中的queued/未派发及额度被直接恢复使用 | 先隔离受回退影响的模型执行、投递和额度，以未回退可信证据核对；不能凭旧状态或查询无结果认定未调用，不能释放已用额度 |
| SDK默认重试、provider去掉参数/参考后再试 | 请求前做能力校验，禁隐式重发；不改变已确认输入 |
| 同提示词候选批量调用 | 原型n=1串行；正式十位置独立计划，候选数与请求数分开记账 |
| 原任务模型重试覆盖同一尝试 | 保留原尝试、首轮和费用；显式模型重试追加新操作/尝试，原输入的零模型本地恢复另留阶段记录 |
| 取消后抛弃返回文件或继续合成 | 迟到归原尝试留档，默认待定；取消后不继续后续阶段 |
| 共享登录开关、旧图库/预览/文件入口 | 全部纳入当前身份与根资源授权；不能用隐藏按钮代替鉴权 |
| FileResponse或预签名链接当成功下载 | 区分预览、传输中断和完整下载；具体版本事件与租约保护 |
| 删除开关或bucket TTL当回收站 | 实现30+7、恢复、历史保护、引用和GC互斥；保留业务记录 |
| 引用保护被当作可以直接读取回收站底图 | 保护只阻止物理清理；新的文件修改需用户确认后系统恢复，恢复失败或拒绝则阻止。超7天仅在文件尚存、未开始清理且有权限时可恢复 |
| 文件不可用连带禁止反馈和关闭事项 | 授权用户仍可修改记录、撤销当前选择和关闭未决事项；已结算首轮保持不变 |
| 挂回主图将AI输出标作商品原图，挤掉真实原图 | 展示选择与事实证据分开；保留真实商品原图、来源及事实版本，AI图不得变成新事实 |
| 模板生成假装文本模型成功 | 文本准备失败保留草稿及具体原因，人工文案模式须显式且FR05未验证 |
| UI locale、市场或旧template_language隐式决定新文案语言 | 中文/马来语/印尼语/Filipino独立选择，默认中文；生成对应预览并确认后再合成，不自动补发文本请求 |
| 整项删除沿用整树物理删除，或商品编辑权扩大到个人任务 | 所有商品/任务/会话整项删除均归档；允许运行中归档，已接受工作继续，新内容/生产先取消归档；关联根独立授权，图片时钟不变 |
| 复用成品只复制顶层记录，目标改字仍须源负责人恢复底图 | 同时建立目标图层及必要依赖记录，目标恢复校验目标权限；依赖不全时不伪报可编辑复用成功 |
| 本地阶段报错立即结算首轮，超时无限自动恢复 | 不改输入/配置的零模型恢复归原尝试，超时停止自动恢复并等待用户继续或结束 |
| 已完成任务因已关闭等待的迟到成品自动变未完成 | 迟到先归历史，用户主动纳入才重评；历史反馈和未结算R0独立处理 |
| 旧版切流后仍持续接收提前修订 | 退出时原子关闭旧轮追加入口，只收尾已接受集合，新修改保留草稿待明确确认新轮 |
| 用户撤权直接把此前已接受操作取消或判失败 | 阻止失权用户新提交，已接受工作按原快照继续，当前有权者通过显式取消停止存量 |
| 设置解锁代替管理角色，或导出回传provider密钥 | 完整配置/导入导出校验管理角色加独立解锁；普通业务只读脱敏运行时能力，读取/预览/导出不回传已保存密钥 |
| 模型请求成功数被当作首轮完整位置数 | 合成前取消且无明确首次失败的原位置仍不完整，不能据十张底图宣布7/10达标 |
| 撤回已生成修改却保留待定候选并直接完成 | 该修订版记弃用，保留旧当前版及历史，重新检查其余事项；不删图、不调用模型 |
| 旧前端规范要求反复获取完整工作流 | 使用product-workflow-status轻量轮询及状态合并，产物变化/完成时才刷新完整数据 |

修改行为时同步相关旧测试和规范，依据新契约修改预期；不能仅删除失败测试或恢复已取消的需求。
