# M1-01 synthetic verification guide

[中文](M1-01-VERIFICATION.md). This slice runs only in a dedicated verification instance. It provides prototype tasks/ten slots, preview confirmation, request accounting, Outbox delivery, shared quotas, unknown outcomes, explicit retries/cancellation, local recovery and temporary deletion protection. Real providers, composites, adoption/R0, named accounts, archive/retention and production deployment remain outside this slice. The [PRD](PRD.md) remains authoritative.

Use `scripts/verify_m101.py --run-id <run-id>` with the verified Python 3.12 environment. Do not use the existing Windows launcher or `.env.dev`. The manifest under `.local/verification/m1-01/<run-id>/` owns the database cluster/roles, Redis namespace/queue, directories, ports and cookie. Generated private credentials stay in that directory and must not enter reports or Git. Dependencies remain locked; frontend preparation uses the existing Node 22/pnpm 10 offline cache.

Run `print-plan`, `prepare`, `preflight`, `migrate --stage expand`, `migrate --stage head`, `seed`, then `prepare-web`. These actions do not reset an existing experiment. Revision 0030 commits enum expansion separately; 0031 creates records/quarantines unverified legacy work, 0032 enforces ownership/immutability, and 0033 appends quarantine digests. A later failure cannot undo the enum commit. Empty-database and staged migration checks use separate registered fixture databases.

Run Ruff and backend pytest through `run --mode unit -- ...`; use `run --mode integration -- python -m pytest -c backend/pyproject.toml backend/integration_tests -q` for real isolated PG/Redis tests. Run `pnpm --dir web lint`, `test:run`, and `build` through unit-mode runner. The Chinese guide lists the exact commands. Integration tests own their worker lifecycle: use `pause-delivery` before rerunning them after browser services started, and `resume-delivery` afterward. A missing final fresh fixture can be appended with `add-fixture --fixture-suffix fresh_final`; an existing database is never reset or adopted.

Start `start-app`, then `start-web`. Sign into the manifest's Web port using its disposable verification key. The current workbench UI supports Chinese only; legacy non-Chinese UI preferences are ignored and there is no UI language picker. Open the synthetic product listed in `evidence/seed.json` and expand 原型验证 (Prototype verification). Image copy independently supports Chinese (default), Malay, Indonesian, and Filipino. Save SKU/content language, prepare and inspect ten copy previews, confirm the matching revision, then explicitly submit ten slots. Canvas Run All remains separate. Opening the Chinese UI does not translate historical copy or trigger model requests.

Outputs are undecided bases. They do not establish finished deliverables, adoption, completion or first-round quality. Test-only dimensions are not the frozen garment specification. Close an unknown wait before a new attempt and acknowledge possible duplicate charges; the original attempt/quota remains. Continue/end local recovery consumes no new model request. Conflicts retain drafts. Cancellation is terminal and late results remain with their original attempt. Ledger-linked deletion is blocked in this verification instance; production archive/retention is not implemented.

Keep `commands.jsonl`, failed and successful logs, the independent `stub-requests.jsonl`, database/response hashes and browser screenshots. Stub costs are not_applicable, not evidence of real pricing. `stop --run-id <run-id>` stops only owned PIDs whose creation times match and retains all data. On migration/startup failure, stop and preserve evidence; do not downgrade the ledger, restore a business snapshot or start an unverified old worker. Historical real model records are preserved. This guide does not authorize M2, real requests or deployment.
